# تقرير الاستهلاك والميزانية

**الأرقام أدناه نموذج ومعايرة كود محلية؛ لا توجد قياسات فوترة فعلية قبل/بعد من حساب Firebase.** لا تُقسَّم زيادة7300 قراءة على20 صنف لإنتاج تكلفة موثوقة.

## مصادر الاستهلاك

| المسار | قراءة/كتابة المصدر |
|---|---|
| فتح الجرد | مستند تحكم، حملة، مجموعات الحملة، جميع أصناف الحملة، وإعدادات الهوية/الصلاحيات عند تشغيلها |
| العد الطبيعي قبل التعديل | 4 قراءات معاملة +2 كتابة؛ قد تتكرر القراءات عند تعارض المعاملة |
| العد الطبيعي المقترح | 4 قراءات معاملة +1 تحقق سجل server-only +2 كتابة |
| إعادة إرسال عملية مؤكدة | قراءة سجل واحدة؛ صفر كتابة في المسار المختبر |
| عملية مجهولة لا سجل لها | قراءة تحقق أولية ثم4 قراءات معاملة ثم1 تحقق؛2 كتابة إذا نجحت |
| found_later | سجل إضافي مشروط في المصدر؛ يزيد كتابة واحدة |
| الملاحظة المقترحة | نفس نمط4+1 قراءة و2 كتابة، مع التحقق من الإغلاق والتزامن |
| listeners للأصناف | تحميل أولي لنتائج الاستعلام، ثم مستندات متغيرة لكل مشترك؛ ليس كامل المجموعة بعد كل عد |
| الإدارة/المحاسب | بيانات الحملة والمجموعات والأصناف؛ الإدارة تضيف سجل تدقيق حتى300 مستند |
| site_sessions المشترك | كان80 كتابة/ساعة؛ أصبح40 في الساعة تحت الساعة الوهمية، إضافة بداية الجلسة |
| v44_presence |40 كتابة/ساعة مستقرة، إضافة انتقالات الحالة |
| runtime الموظف الرئيسي | site_sessions وusers كل90 ثانية؛ نحو80 كتابة/ساعة إضافية إذا كانت تلك الصفحة مفتوحة |
| النشاط | سجلات نقر/بحث/فتح/إغلاق؛ جزء منها محدود زمنيًا لكنه ليس صفرًا |
| السلة | فحص محلي كل2.5 ثانية؛ الكتابة عند اختلاف المحتوى، وليس كل فحص |
| العملاء | جلسات/طلبات/مسودات/رسائل وصلاحيات؛ تختلف التكلفة حسب نوع الجلسة والصفحات |
| الاستيراد/الصور | أجزاء تعتمد GitHub/Vercel وأجزاء تدقيق Firestore؛ لا تُنسب كل حركة صورة إلى الجرد |

لـonSnapshot رسوم عند تغير المستندات؛ إعادة الاتصال بعد انقطاع طويل قد تعيد تكلفة الاستعلام. مصدر Google: https://firebase.google.com/docs/firestore/pricing . الحدود اليومية الرسمية50,000 قراءة،20,000 كتابة،20,000 حذف، مع إعادة ضبط بتوقيت المحيط الهادئ لا منتصف الليل السعودي: https://firebase.google.com/docs/firestore/quotas . القواعد قد تضيف قراءات تحقق لا يحصيها النموذج.

## نتائج التنفيذ المعزول

انظر `browser-results.json` و`core-results.json`. نُفذ كود التطبيق في Chromium مع بديل Firestore متفائل يدعم إعادة محاولة المعاملة. هذا البديل لا يحاكي شبكة Firebase، listener fanout، القواعد، التخزين المفهرس الحقيقي أو الفوترة.

## نموذج يوم تشغيل 8 ساعات — افتراضات قابلة للتغيير

1500 صنف إجمالي موزعة750/750،4 أجهزة لكل فرع،1500 عملية عد، تحميل أولي واحد، لا إعادة اتصال شاملة، ومراقب جرد واحد يتابع كل حملة مرة. لا تشغيل متزامن لصفحات المراقبة العامة أو واجهة المخزون على أجهزة العد. هذه **شروط النموذج وليست قياسات الإنتاج**.

- تحميل الأصناف على الأجهزة:6000 قراءة، إعدادات/مجموعات نحو56 في الاختبار.
- العد + التحقق:7500 قراءة و3000 كتابة.
- انتشار تحديثات الأصناف إلى4 أجهزة/فرع:نحو6000 قراءة.
- تحميل الإدارة1500 صنف ثم تحديثاتها1500 وسجل العمليات حتى1500:نحو4500 قراءة، إضافة البيانات الوصفية. حملة واحدة معروضة في المرة؛ لا نعتمد حد300 كسقف يومي مضمون للقراءات.
- حضور ثمانية أجهزة ثماني ساعات: كان7680 كتابة للمسارين، يصبح5120، باستثناء بدايات الجلسات وانتقالات الحالة.
- مراقب حضور واحد يستمع إلى مجموعتي الحضور يمكن أن يضيف نحو5120 قراءة بعد التحسين.
- مجموع النموذج الموسع بعد التعديل:نحو29,176 قراءة و8120 كتابة، قبل النشاط التجاري والتدقيق الإضافي والنسخ الاحتياطي والقواعد وإعادات المحاولة.
- قبل التعديل نفسه:نحو30,236 قراءة و10,680 كتابة. زيادة تحقق السجل تستهلك1500 قراءة، بينما خفض الحضور يوفر2560 كتابة، ونحو2560 قراءة إذا كان مراقب الحضور موجودًا. غياب المراقب يغيّر المقارنة.

الميزانية الأولية المقترحة للجرد والمراقبة: **حد داخلي35,000 قراءة و12,000 كتابة**؛ المتبقي للتجارة والطوارئ15,000 قراءة و8000 كتابة. هذه حصة محجوزة مستهدفة، وليست حصة متبقية مؤكدة أو ضمانًا للكفاية. تحميل أولي متكرر للأجهزة الثمانية قد يضيف6000 قراءة في كل جولة ويستهلك الهامش سريعًا. لا عمليات حذف مطلوبة لمسار العد.

فتح الصفحة مجددًا: يتراوح بين استفادة محلية وبين إعادة قراءة الحملة كاملة؛ لا نعده صفرًا. لا يمكن إثبات خمول الموقع كله من مؤقت الجرد فقط. فتح command-center قد يحمّل آلاف سجلات مختلفة.

## القياس المطلوب قبل الاعتماد

توصيل Firebase بصلاحية القراءة للقواعد والاستخدام والبيانات المطلوبة، وتحديد جميع الصفحات/الجلسات المفتوحة. تسجيل خط أساس10 دقائق ثم عد10 و100 صنف في مشروع اختبار منفصل أو محاكي، مع عدادات محلية للاشتراكات والمعاملات ونشر التحديثات. قياس خمول جهاز/ثمانية أجهزة، فتح الإدارة، إعادة التحميل، انقطاع1/10/35 دقيقة، ونشاط التجارة. لا تُجرى تجربة حمل على الإنتاج. تُقارن نافذة القياس مع مقاييس Google المؤخرة، وتُحسب قراءات القواعد والتكرار ونسخة احتياطية مستقلة ضمن الميزانية.
