# خطة حماية البيانات واستعادة المسودات

## المسودات الأربع الموجودة

1. الحفاظ على الهاتف والمتصفح أو التطبيق المثبت والنطاق نفسه. عدم حذف التطبيق أو بيانات الموقع، وعدم تبديل طريقة الفتح على افتراض أن التخزين مشترك.
2. قبل ترقية صفحة العمل، أخذ نسخة قراءة فقط من المفاتيح `stocktake.draft.v73:` باستخدام جهاز الموظف أو جلسة فحص Safari موثوقة. لا تُطلب كلمة مرور أو مفتاح خدمة في المحادثة. لا يمكن الوصول لهذه المفاتيح من GitHub أو Vercel.
3. لم يُنشر زر الاستعادة المقترح بعد. بعد استكمال شروط نشره، يُفتح على **النطاق الإنتاجي نفسه**؛ رابط Preview له تخزين مستقل ولن يعرض مسودات الهاتف القديمة.
4. تصدير JSON قبل إعادة الإرسال. الاحتفاظ بالنسخة في مكانين يتحكم بهما المسؤول. يتضمن الخام والمعرفات والقيم، ويجب التعامل معه كبيانات عمل خاصة.
5. العملية ذات operationId: قراءة `stocktake_audit/<id>` من الخادم ومطابقة البيانات. إن تطابقت تُسوى دون كتابة كمية. إن غاب السجل تُراجع الحالة الحالية قبل إعادة نفس المعرف. عدم افتراض أن «لا يوجد رد» يعني فشل العملية.
6. العملية بلا معرّف أو ذات سجل لا يطابق: مراجعة إدارية يدوية بين القيمة والمساهمات والسجل الزمني؛ لا اختلاق تأكيد ولا إنشاء عملية جديدة تلقائيًا.

**لم تُنفذ هذه الخطوات على الهاتف، ولا نعلم أرقام الأصناف الأربع بعد.**

## الضمانات والمخاطر

المقترح يمنع إزالة مسودة لم يثبت سجلها، ويحافظ على العملية عند المهلة/نفاد الحصة. لكنه لا يحمي من حذف المستخدم لتخزين المتصفح أو تلف الجهاز. JSON المحلي خطة احتياطية، وليس بديلاً عن سجل سحابي موثوق. الحماية داخل JavaScript ليست صلاحية أمنية؛ يلزم Auth وقواعد Firestore منشورة ومختبرة.

يلزم أن تمنع Rules حذف الحملات النشطة وتعديل expectedQty بعد البدء، وأن تجعل سجلات التدقيق append-only، وتتحقق من ربط الموظف بالمجموعة والحملة ومطابقة الكتابات الذرية. يجب تصميم ذلك بعد قراءة المخطط والقواعد الحالية؛ تطبيق قواعد مفترضة الآن قد يوقف التجارة.

لا يستطيع المدير معرفة المسودات الموجودة على أجهزة غير متصلة. الإغلاق الآمن يحتاج سجل أجهزة/مجموعات وإقرار إنهاء لكل جهاز مع صفر عمليات معلقة، ثم منع عمليات جديدة وإغلاق ذري. غياب جهاز لا يُعامل كإقرار نجاح. هذه آلية غير منفذة بعد، لذا لا يُعتمد الجرد السنوي.

## نسخ احتياطي مقترح ضمن التكلفة

قبل بدء الجرد: نسخة من الحملات والمجموعات والأصناف المرجعية وإعدادات التوجيه والقواعد/الفهارس، مع توقيت ومعرف المصدر وSHA-256 لكل ملف. أثناء الجرد: تصدير محلي للعمليات المعلقة ونسخ دورية لسجلات العمليات المؤكدة، مع احتساب قراءات النسخ في الميزانية. عند النهاية: JSON كامل + Excel للنتائج + سجل العمليات والملاحظات؛ Excel وحده لا يحفظ كل خصائص Firestore وأنواعها.

وظائف النسخ المدارة وPITR ليست ضمن الاستخدام المجاني وفق https://firebase.google.com/docs/firestore/quotas . لا تُفعّل خدمات مدفوعة دون قرار المالك. التصدير المقترح على Spark يقرأ المستندات ويستهلك الحصة ويحتاج صلاحية مناسبة.

اختبار الاستعادة المطلوب: مشروع/محاكي منفصل، استيراد النسخة مع حفظ المعرفات والأنواع، مقارنة أعداد المستندات وhash للمحتوى وتقرير الفروقات؛ إعادة العمليات بنفس المعرف وإثبات عدم الازدواجية. لا استيراد فوق الإنتاج ولا حذف تجريبي عليه. هذا الاختبار لم يُنفذ لغياب نسخة مصرح بها وبيئة Firebase المعزولة.
