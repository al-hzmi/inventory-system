# تقرير الاختبارات وحدود الدليل

## نفذ محليًا ونجح

- مطابقة سجل العملية: الحملة/المجموعة/الصنف/الموظف/الفعل/الكمية. رفض القيم الناقصة وNaN والهوية المختلفة.
- التخزين: كتابة وقراءة، امتلاء التخزين، عدم استبدال مسودة سابقة عند الفشل، الاحتفاظ بالنص التالف، عدم حذف سجل تغير أثناء التحقق.
- متصفح Chromium ببديل Firestore: عد واحد، إعادة تأكيد عملية محفوظة بلا كتابة إضافية، الاحتفاظ بالمسودة عند رفض السجل، عرض الاستعادة وتصدير الملف، بقاء المسودة بعد إعادة التحميل.
- محاكاة resource-exhausted ثم نجاح نفس operationId؛ محاولة تغيير كمية عملية معلقة مرفوضة مع بقاء القيمة السابقة.
- تأخير حقيقي19 ثانية: تنتهي مهلة18 ثانية بلا نجاح وهمي، ثم يُثبت السجل ويحذف المسودة دون كتابة ثانية.
- حفظ ملاحظة ذرية، ونسبتها للمجموعة الحالية، ورفض الحملة المغلقة من معاملة الخادم البديل.
- متصفحان يعدلان المجموعة والصنف نفسيهما: نجاح واحد ورفض الآخر كـconflict مع بقاء المسودة.
- مجموعتان في نطاقين مختلفين: بعد عرض قديم يُرفض الاعتماد مؤقتًا، ثم بعد تحديث البيانات والمراجعة تُحفظ مساهمتا 2 و3 دون استبدال إحداهما.
- إعادة تحميل الصفحة أثناء الحفظ، انقطاع الاتصال المُحاكى عبر حالة navigator، استئناف بنفس المعرف، فشل قراءة إيصال العملية، ورفض إيصال من cache.
-6 و8 سياقات متصفح، حملتان مستقلتان،1500 صنف لكل تجربة:1500 نجاح و0 مسودة معلقة نهائية،3000 كتابة و7500 قراءة معاملة/إيصال. راجع JSON للأزمنة المحلية؛ ليست زمن Firebase أو زمن آيفون.
- اختبار ساعة وهمية لكود الحضور قبل/بعد:80 ←40 كتابة مستقرة/ساعة؛ موجة20 حدث عودة:20 ←0 كتابة إضافية.
- اختبارات المصدر: V73-data، V89-cross-page-syntax، V95، V99، V106، V115، V116.
- `npm run build`: نجح،4 صفحات مترجمة قبل النشر. مخرجات البناء لم تدخل التعديل المقترح.

## فشل أو لم يُثبت

اختبار V79 القديم يفشل بتوقع رابط branch-stocktake.html داخل admin-stocktake-shell.html، وهو غائب في V116 قبل هذا الفرع؛ لم يتغير ملف shell في الإصلاح. لا تُسجل هذه الحالة كنجاح. اختبار V73-browser القديم يستخدم batch فقط ولا يوفر runTransaction؛ لا يصلح كدليل لمسار V116 الحالي، ولم يُستخدم بديلًا عن اختبارات الاستعادة الجديدة. يلزم تحديث بقية الاختبارات التاريخية قبل إعطاء اعتماد شامل.

لم يُشغّل محاكي Firebase الحقيقي أو اختبار Rules، ولا اختبار iPhone/Safari فعلي أو قتل تطبيق iOS/إعادة تشغيل الهاتف أو10 دقائق انقطاع فعلي أو تبديل شبكة حقيقية. لا يوجد قياس billable reads، ذاكرة الهاتف أو ضغط المستمعين الحقيقي. بديل قاعدة البيانات لا يبث تحديثات كل العملاء لحظيًا؛ اختبار الحمل يثبت مسار المعاملات والإيصالات فقط، لا جودة listener fanout أو مزامنة العرض. لم تُختبر كل المزايا التجارية E2E، ولا إغلاق مع أجهزة غير متصلة، ولا استعادة نسخة احتياطية سحابية.

## إعادة التنفيذ

```sh
npm ci --ignore-scripts
npx playwright install --with-deps chromium
node tests/recovery-core.cjs
node tests/recovery-browser.cjs
node tests/v73-stocktake-data.cjs
node tests/v89-cross-page-syntax.cjs
node tests/v95-login-stocktake-integrity.cjs
node tests/v99-integrity-recovery.cjs
node tests/v106-observability-write-budget.cjs
node tests/v115-stocktake-source.cjs
node tests/v116-dual-branch.cjs
npm run build
```

البناء يعدّل HTML محليًا؛ ينفذ في checkout مخصص للبناء. اختبارات المتصفح تعترض جميع طلبات الشبكة وتستخدم localhost وبيانات وهمية، ولا تسمح بطلبات إنتاج.

## نتائج GitHub Actions الإضافية

ظهرت إخفاقات فعلية في فحوص قديمة لصفحة العميل ونسخ service worker (V43 وV56.11 وV89). ملفات customer-sw.js وsw.js والاختبارات المعنية لم تتغير في الفرع، لكن ذلك لا يثبت سلامة السلوك الحالي: تحتاج فحصًا وتحديث اختبارات يستند إلى السلوك. بقية الفحوص كانت جارية عند المراجعة. لا يجوز الدمج ما دام الفشل دون معالجة.

تحديث: اختُبر تداخل تسوية الإيصال مع وصول رد المعاملة بنجاح محليًا، مع الاحتفاظ بمهلة التأكيد المتأخر. فشل فحص الاستعادة السابق على GitHub قبل الاختبارات لأن Playwright لا يدعم ubuntu-latest (26.04)، فثُبتت بيئة CI على ubuntu-24.04 لإعادة المحاولة. نتيجة التشغيل الجديد لم تتأكد بعد.
